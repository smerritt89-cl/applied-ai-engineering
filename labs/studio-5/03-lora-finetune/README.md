# Lab 03: LoRA fine-tuning, measured

**Goes with:** Studio 5, week 3 (lessons 7 to 9). **Time:** about 90 minutes (30 offline, 60 for the training run).

## Goal

Fine-tune a small open model with LoRA so it triages support tickets into a fixed JSON format, and judge the result
with a baseline, a held-out test set, and a strict scorer rather than the training loss.

- **Model:** [`Qwen/Qwen2.5-0.5B-Instruct`](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct), Apache 2.0 (license
  checked on the model card on the review date). Small enough to train in minutes on a free Colab GPU or a Mac.
- **Data:** `data/*.jsonl`, about 400 synthetic tickets generated by `make_lora_data.py`. Each record has a `ticket`
  and a `label` with `category`, `priority`, `product` (or null), and `order_id` (or null). The test split uses
  sentence templates that never appear in training, so it measures generalization rather than recall.

## Steps

1. **Offline part.** Fill in `starter.py` until the tests pass:

   ```bash
   cd labs && source .venv/bin/activate
   pytest studio-5/03-lora-finetune -q
   ```

   One test (`test_lora_count_matches_peft_on_a_tiny_model`) is skipped unless torch, transformers, and peft are
   installed. To run it: `pip install torch "transformers==5.22.2" "peft==0.21.2"`. It builds a tiny random Qwen2
   model on the CPU (no download) and checks your count against PEFT's.

2. **Training run, option A (Colab, NVIDIA GPU).** Use the *Open in Colab* link on the lesson page, choose a GPU
   runtime, and run the cells in order. The notebook clones this repo, imports the reference helpers, and walks the
   five checkpoints: template check, baseline, parameter count, training with loss curves, and the tuned score.
   Change `import solution as lab` to `import starter as lab` once your tests pass.

3. **Training run, option B (Apple Silicon Mac).** In a venv:

   ```bash
   pip install "mlx-lm[train]==0.32.2"
   python studio-5/03-lora-finetune/mlx_finetune.py          # QLoRA: 4-bit base model
   python studio-5/03-lora-finetune/mlx_finetune.py --bf16   # LoRA: bf16 base model
   ```

   It uses your `starter.py` if it's complete, and `solution.py` otherwise. Losses go to
   `mlx_runs/log.jsonl`, which your `parse_mlx_jsonl` reads.

4. Write down, for each run: base scores, tuned scores, the loss diagnosis, and three failures you read yourself.

## Expected cost

Free. No API calls. Colab's free tier gives you a GPU when one is available (types and limits vary and are not
guaranteed). On an Apple Silicon Mac the MLX run downloads about 300 MB for the 4-bit model.

## What to notice

- **Base versus tuned.** In one MLX test run during authoring (4-bit model, 150 iterations, on an Apple Silicon Mac),
  the base model produced valid JSON for every test ticket but got only 2 percent exactly right; it invented products
  and mixed up categories. The tuned adapter reached 52 percent exact match and 88 percent field accuracy. Your
  numbers will differ with hardware, versions, and seeds. The point is the shape: format improves first and most.
- **Failures the loss never shows.** That run's remaining errors were instructive: shipping tickets with an unseen
  sentence pattern labeled `bug`, and order ids invented for tickets that had none (one output was `"chango.500"`,
  built from "500 error" in the ticket). A one-line check would catch the second kind: an `order_id` must appear
  verbatim in the ticket. That's the Studio 1 evidence check, applied to your own model.
- **Overfitting on synthetic data.** Training loss drops near zero within a few dozen steps because the templates are
  easy to memorize, while validation loss bottoms out and creeps up. `diagnose` should flag it. Try fewer steps or
  a lower learning rate and compare the *test scores*, not just the losses.
- **Framework knobs differ.** PEFT scales the adapter by `lora_alpha / r`; MLX-LM takes a direct `scale` (its
  default is 20.0 with learning rate 1e-5). The MLX script uses `scale=2.0` to match `r=16, lora_alpha=32`.
- **Forgetting.** Ask the tuned model a general question with no system prompt and compare with the base model.
  Week 4 measures this properly.
