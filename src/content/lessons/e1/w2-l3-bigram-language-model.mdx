## What a language model is

A language model assigns a probability to a sequence of tokens. By the chain rule of probability, any distribution over sequences factors exactly as a product of next-token conditionals: P(c1, ..., cT) = P(c1) times P(c2 given c1) times ... times P(cT given c1 through cT minus 1). This is not an approximation; it's an identity. An autoregressive model, which GPT is, learns those conditionals directly, and generating text means sampling from them one token at a time.

The approximation comes from what you allow each conditional to see. A **bigram** model assumes the next character depends only on the current one: P(ct given everything before) is replaced by P(ct given ct minus 1). That's a first-order Markov chain over characters. It is a terrible model of language and a perfect place to learn the whole framework, because you can fit it by counting, check it by hand, and then rebuild it as a neural network and watch both agree.

The dataset is makemore's `names.txt`: 32,033 names, one per line. Each name becomes a short sequence wrapped in a special token, written ".", that marks both the start and the end. With 26 letters plus ".", the vocabulary has 27 tokens.
</Listen>

## Counting is maximum likelihood

Write n_ij for the number of times token j follows token i in the training data. The model's parameters are the conditional probabilities p_ij, one distribution per row i, with each row summing to 1. The log-likelihood of the data is the sum over all pairs of n_ij log p_ij.

Maximize it row by row, subject to the row constraint. With a Lagrange multiplier lambda for row i, setting the derivative of (sum over j of n_ij log p_ij, minus lambda times (sum over j of p_ij minus 1)) to zero gives n_ij / p_ij = lambda, so p_ij is proportional to n_ij, and normalizing gives p_ij = n_ij divided by the row total n_i. The maximum likelihood estimate is just the row-normalized count matrix.

That's what the video calls "training the model" at 12:45: counting is the closed-form solution of the same optimization problem that gradient descent solves approximately in the second half. Having a closed form is rare, and it gives you a precious thing for the rest of the lecture: a known right answer to check the neural network against.
</Listen>

```text
maximize    sum_j n_ij log p_ij      subject to   sum_j p_ij = 1

Lagrangian  sum_j n_ij log p_ij - lambda (sum_j p_ij - 1)
d/dp_ij:    n_ij / p_ij - lambda = 0   =>   p_ij = n_ij / lambda = n_ij / n_i
```

## Scoring a model: negative log-likelihood

The likelihood of the dataset is the product of the probabilities the model assigns to every bigram that actually occurs. That product is a tiny number (thousands of factors below 1), so you work with its logarithm, which turns the product into a sum. Flip the sign so that lower is better, and divide by the number of bigrams so the loss doesn't depend on dataset size. That's the **average negative log-likelihood** (NLL), which for classification is the same quantity as **cross-entropy** between the data and the model.

Anchor it with two reference points. A model that assigns every token probability 1/27 scores log 27, about 3.296, on any data. A perfect model scores 0. For this lesson, the counting model was fit to all of `names.txt` with the method in the video, and its average NLL on that same data comes out at about 2.454. So the bigram structure is real (it beats uniform comfortably), and there's lots left to learn.

Exponentiate the NLL and you get **perplexity**, the effective number of equally likely choices the model is torn between at each step: about 27 for the uniform model, about 11.6 for the bigram model. You'll see perplexity in older papers and NLL (often called "loss") in nearly everything recent.
</Listen>

<Callout type="pitfall" title="Measuring on the data you trained on">
The 2.454 above is a **training** loss: the model was fit to those exact names. For a counting model with 729 parameters and 228,146 bigrams that's nearly the same as a held-out loss, but the gap grows with model size, and by lesson 4 it's the whole story. The video's exercise E02 asks you to split the names 80/10/10 into train, dev, and test sets. Get in the habit now: a loss number means nothing until you know which data it was measured on.
</Callout>

## Smoothing: when the data says "never"

Of the 729 possible bigrams, 102 never occur in `names.txt`; "jq" is one. The maximum likelihood estimate gives them probability exactly 0. Evaluate on any name containing one, and a single factor of 0 makes the likelihood 0 and the NLL infinite.

The fix at 01:00:50 is to add a fake count, say 1, to every cell before normalizing. In Bayesian terms, that's the posterior mean under a symmetric Dirichlet prior on each row (adding 1 everywhere is Laplace smoothing). The pseudo-count is a knob: 0 is the pure MLE; a huge value drags every row toward uniform. Its right value is an empirical question you answer on a dev set, which is exactly exercise E03 in the video description.

Notice the trade-off in miniature, because it recurs in every model you'll train: smoothing slightly raises the training loss (the MLE is, by definition, optimal on training data) in exchange for robustness on data the model hasn't seen.
</Listen>

## The same model as a neural network

The second half of the video rebuilds the bigram model with gradient descent, and this is where it starts looking like deep learning. Encode the current character as a **one-hot** vector x in R^27 (all zeros except a 1 at its index). Multiply by a 27 by 27 weight matrix W to get 27 numbers called **logits**. Exponentiate and normalize (the **softmax**) to get a probability distribution over the next character. The loss is the same average NLL. Backpropagate and step W.

Two notes in the video tie this back to counting. First (01:47:49), x times W with a one-hot x just **selects row i of W**. So the network is a lookup table of logits, one row per current character, and an embedding layer in a transformer is the same idea: indexing a matrix instead of multiplying by a one-hot vector. Second, the softmax of row i is the model's P(next given i). The NLL is minimized when that softmax equals the empirical row distribution, which happens when the logits equal log counts plus any per-row constant. So gradient descent converges toward the counting model: exp of the logits plays the role of the counts.

The second note (01:50:18) maps smoothing onto the network: adding a penalty proportional to the mean of W squared pulls all logits toward 0, which pushes every row toward uniform, exactly what pseudo-counts do. Regularization in neural networks is, very often, a prior in disguise.
</Listen>

```text
logits      z = x W                  (x one-hot  =>  z = W[i, :])
softmax     p_j = exp(z_j) / sum_k exp(z_k)
loss        L = -log p_y

Jacobian    dp_i/dz_j = p_i (delta_ij - p_j)
gradient    dL/dz_j  = p_j - [j == y]          (softmax minus one-hot)
```

## Softmax, worked out

Softmax maps any real vector z to a probability vector: p_j = exp(z_j) divided by the sum of exp(z_k). Three properties matter constantly. It is invariant to adding a constant to every logit (the constant cancels), which is why implementations subtract the maximum logit before exponentiating to avoid overflow. It preserves order (bigger logit, bigger probability). And its Jacobian is dp_i/dz_j = p_i times (delta_ij minus p_j), a symmetric matrix equal to diag(p) minus p p transpose.

Compose that Jacobian with the loss L = minus log p_y and the chain rule collapses beautifully: the gradient with respect to the logits is p minus the one-hot vector for the target y. Read it as a force: push up the logit of the correct character by (1 minus its probability), push down every other logit by its probability. When the model is confident and right, the gradient vanishes; when it is confident and wrong, the push is nearly 1. You'll implement and gradient-check this in the next lesson, and derive it again for whole batches in lesson 6.
</Listen>

<GoDeeper title="Why NLL is the loss, from three directions">
**Statistics:** minimizing average NLL is maximizing likelihood, the standard estimator for a parametric model (chapter 5.5 of Goodfellow, Bengio, and Courville). **Information theory:** the average NLL of the data under the model is the cross-entropy H(data, model), which equals the entropy of the data plus the KL divergence from the data distribution to the model. The entropy is fixed, so minimizing NLL minimizes KL divergence, and the loss can never go below the data's own entropy. **Compression:** an NLL of 2.454 nats per character is 2.454 / ln 2, about 3.54 bits, the code length an arithmetic coder driven by this model would need per character. A better language model is literally a better compressor, which is a useful intuition for what pretraining optimizes.
</GoDeeper>

## Review sheet

A language model factors a sequence probability into next-token conditionals (exact), then limits what each conditional sees (the approximation). Counting and normalizing rows is the maximum likelihood estimate. Average NLL is the loss; log V is the uniform baseline (3.296 for 27 tokens), and the counted bigram reaches about 2.454 on the names. Smoothing adds pseudo-counts to avoid infinite loss on unseen events, at a small cost in training loss. A one-hot times a matrix selects a row; softmax of learned logits recovers the counts; the gradient of NLL with respect to logits is softmax minus one-hot. Always check rows sum to 1, and always say which data a loss was measured on.
</Listen>
