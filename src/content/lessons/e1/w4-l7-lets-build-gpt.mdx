## From makemore to GPT

Everything so far has been a model that reads a fixed, short context and predicts the next character. "Let's build GPT" keeps that framing (a character-level, autoregressive language model) and changes one thing: how a position gathers information from the positions before it. In the MLP, the context was concatenated and pushed through fixed weights. In a transformer, each position computes a **data-dependent weighted average** of the earlier positions, called self-attention, and stacks of those averages, interleaved with per-position MLPs, make up the model.

The lecture trains on "tiny Shakespeare," about a megabyte of Shakespeare's plays as one text file, with a vocabulary of the characters that appear in it. It starts from a bigram baseline, builds attention in four versions, assembles transformer blocks, scales up, and ends with a model of about ten million parameters (about 10.8 million if you count the layers in its `gpt.py` with a 65-character vocabulary) that writes plausible-looking pseudo-Shakespeare. The code it builds is published as `ng-video-lecture` (MIT), and Karpathy's `nanoGPT` repository is the cleaned-up, faster version.

The description recommends watching the makemore lectures first, which you have. The tensor operations that the video takes for granted are now the ones you've derived.
</Listen>

## One chunk, many training examples

The data loader samples random chunks of block_size + 1 consecutive tokens. A chunk of length T + 1 contains T examples at once: token 1 predicts token 2, tokens 1 and 2 predict token 3, and so on up to all T tokens predicting the last one. Inputs are the first T tokens, targets are the same chunk shifted by one, and the loss averages over all T positions and the whole batch.

This matters in two ways. It's efficient: one forward pass trains every context length from 1 to T. And it means the model must work with any amount of context up to block_size, which is exactly what generation needs, since generation starts from a short prompt and grows. The causal mask you'll build below is what makes this legal: position t must not see tokens after t, or predicting token t + 1 would be trivial.

It also sets the meaning of block_size: it is the context window of this model, the same concept as a frontier model's context window in Studio 1, just a few hundred characters instead of hundreds of thousands of tokens. Positions beyond it don't exist for the model, and the generation loop crops the context to the last block_size tokens.
</Listen>

```text
single head, causal, for positions t = 1..T, head size d:

  q_t = x_t Wq      k_s = x_s Wk      v_s = x_s Wv

  a_ts = (q_t . k_s) / sqrt(d)                  for s <= t   (else -inf: the mask)
  w_ts = exp(a_ts) / sum_{u <= t} exp(a_tu)     softmax over the allowed positions
  y_t  = sum_{s <= t} w_ts v_s                  a convex combination of earlier values

matrix form:   Y = softmax( mask(Q K^T / sqrt(d)) ) V
```

## Attention is a weighted average

The lecture builds up to self-attention in steps that are worth replaying in mathematical terms. Version 1 averages all previous token vectors with loops. Version 2 notices that a running average is a matrix multiply: multiply the (T, C) token matrix by a lower-triangular (T, T) matrix whose row t holds 1/(t + 1) in its first t + 1 entries. Version 3 gets the same matrix by putting zeros on and below the diagonal, minus infinity above it, and applying a softmax to each row. Version 4 replaces those zeros with scores computed from the data.

So each output y_t is a **convex combination** of value vectors v_s for s at most t: the weights are nonnegative and sum to 1. Geometrically, y_t lies in the convex hull of the past values. What the network learns is where to put the weight. Each position emits a query ("what am I looking for"), a key ("what do I contain"), and a value ("what I'll pass on if chosen"); the weight on s is a softmax of how well t's query matches s's key.

The lecture's first note at 01:11:38 calls this communication: tokens are nodes in a directed graph, each aggregating information from the nodes that point to it. With the causal mask, the graph has an edge from every earlier position to every later one. The third note adds that no communication happens across the batch dimension: each sequence is its own graph.
</Listen>

## Why divide by the square root of the head size

Suppose the components of q and k are independent with mean 0 and variance 1. Then q . k is a sum of d independent products, each with mean 0 and variance 1, so it has mean 0 and variance d. That's the argument in footnote 4 of "Attention Is All You Need" (Vaswani and colleagues, 2017). For a head size of 64, raw scores have a standard deviation of 8.

Feed scores like that into a softmax and it saturates: the largest score wins by a wide margin and the weights are nearly one-hot. Two things go wrong. Each token attends to essentially one other token from the very start, before it has learned anything. And the softmax's Jacobian, diag(p) minus p p transpose, is nearly zero when p is nearly one-hot, so gradients through the attention weights vanish. Dividing by the square root of d restores unit variance and keeps the softmax in its responsive range (lecture note 6, at 01:16:56).

This is the same variance bookkeeping as Kaiming initialization in lesson 5, applied to a different product. Once you see deep learning as a long chain of operations whose scales must be kept near 1, a surprising amount of transformer design reads as variance control.
</Listen>

## Attention works on sets, so positions must be added

Lecture note 2 (01:12:46) observes that attention has no notion of space. Formally, self-attention without a mask is **permutation equivariant**: permute the input tokens and the outputs are permuted the same way, because every operation (the projections, the dot products, the softmax over keys, the weighted sum) treats positions symmetrically. Without some positional signal, "dog bites man" and "man bites dog" contain the same multiset of tokens and would get the same per-token representations (the causal mask breaks the symmetry only partially, by restricting who sees whom).

The lecture's fix, at 01:00:18, is a second embedding table indexed by position: the input to the first block is the token embedding plus a learned position embedding, a vector for each of the block_size positions. The original transformer paper used fixed sinusoidal encodings instead; many recent models use other schemes that inject relative position into the attention scores. The common point is that order is information the architecture doesn't provide for free.

One consequence is directly visible in your project: the position table has exactly block_size rows, so a model trained with context 64 has no representation at all for position 65. Context length is baked into the parameters.
</Listen>

## The rest of the block

**Multi-head attention** (01:21:59) runs several smaller heads in parallel, for example 6 heads of size 64 for an embedding of 384, concatenates their outputs, and applies a linear projection. Each head can attend to a different kind of relationship. The suggested exercise EX1 asks you to batch the heads as an extra tensor dimension, which is how nanoGPT does it.

**The feed-forward layer** (01:24:25) is an MLP applied to each position independently, widening to 4 times the embedding size and back. The lecture's summary of the block is communication (attention) followed by computation (the MLP), repeated.

**Residual connections** (01:26:48) write each sub-layer as x plus f(x) instead of f(x). In the backward pass the identity path carries the gradient straight through, so deep stacks remain trainable; this is the ResNet idea (He and colleagues, 2015). Early in training, when f contributes little, the network behaves like a shallow one and gradually brings each block into play.

**LayerNorm** (01:32:51, Ba and colleagues, 2016) standardizes each token's vector across its features, with learned scale and shift. It's BatchNorm transposed: no batch statistics, no train and eval difference, no coupling between examples. The lecture places it before each sub-layer ("pre-norm"), which is the arrangement the GPT-2 paper describes in its section 2.3, along with a final LayerNorm after the last block.

**Dropout** (Srivastava and colleagues, 2014) randomly zeroes activations during training, a regularizer the lecture adds when it scales up (dropout 0.2 in its `gpt.py`, with block_size 256, 384-dimensional embeddings, 6 heads, and 6 layers).
</Listen>

<Callout type="pitfall" title="Bugs that still produce Shakespeare-ish text">
Character-level models generate plausible-looking text even when something is wrong, so samples are a poor test. Three bugs to check for explicitly. **A missing or wrong causal mask** lets positions see the future: training loss drops suspiciously fast and generation is garbage, because at generation time the future isn't there. Test that changing later tokens doesn't change earlier outputs, as the exercise does. **Scaling by the embedding size instead of the head size** (the lecture's own correction at 01:20:05) quietly mis-scales the scores. **Evaluating on one noisy batch** instead of averaging many (the lecture's `estimate_loss` averages 200 batches per split) makes runs look different when they aren't.
</Callout>

## What the trained model shows, and what it doesn't

For calibration, nanoGPT's README reports a best validation loss of 1.4697 for its baby GPT config (6 layers, 6 heads, 384 channels, context 256) after about 3 minutes on one A100 GPU, and about 1.88 for a much smaller CPU config. The samples have the shape of a play, with speaker names, line breaks, and archaic-looking words, and almost no meaning. Those numbers are useful calibration for your project: if your run is far from them with a similar config, look for a bug before tuning.

At 01:48:53 the lecture connects this to ChatGPT. What you built is the pretraining stage: a document completer. The same architecture at vastly larger scale, trained on vastly more data, followed by supervised fine-tuning and reinforcement learning from human feedback, becomes an assistant. That's the arc from Studio 1's first lesson, now with every piece of the first stage in your own code.

<GoDeeper title="Attention as kernel smoothing, and a visual explanation">
If you know nonparametric statistics, attention has a familiar shape: y_t = sum over s of w(q_t, k_s) v_s with weights that are a normalized exponential kernel of query and key, which is a Nadaraya-Watson estimator with learned feature maps. Seen that way, the 1/sqrt(d) factor is a bandwidth, and multi-head attention fits several kernels at once. That's an analogy, not a theorem about what transformers learn, but it's a useful way to remember the mechanics. ## Review sheet

A chunk of T + 1 tokens trains T next-token predictions at once; block_size is the context window. Single-head causal attention: y_t = sum over s at most t of softmax(q_t . k_s / sqrt(d)) v_s, a convex combination of past values. Divide by sqrt(head size) because q . k has variance d. Attention is permutation equivariant, so add position embeddings, which fixes the maximum context in the parameters. A block is x + attention(LayerNorm(x)), then x + MLP(LayerNorm(x)); residual paths keep gradients flowing; LayerNorm normalizes per token.
