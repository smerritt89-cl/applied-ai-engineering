## Derivatives, numerically

For a function f of one variable, the derivative at x is the limit of (f(x + h) minus f(x)) divided by h as h goes to zero. The video estimates it by just picking a small h. That one-sided estimate has error of order h: by Taylor's theorem, f(x + h) = f(x) + h f'(x) + (h squared over 2) f''(x) + ..., so the quotient equals f'(x) + (h/2) f''(x) + higher terms.

The **central difference**, (f(x + h) minus f(x minus h)) over 2h, cancels the second-order term, leaving error of order h squared. With h around 1e-5 or 1e-6 in double precision you get about ten correct digits for well-behaved functions. Push h much smaller and floating-point cancellation takes over: you subtract two nearly equal numbers and lose the digits you wanted.

Numerical derivatives cost one or two extra function evaluations per input. For a network with a million parameters, that's two million forward passes per gradient, which is why nobody trains this way. But they are the perfect **independent check**. Every gradient you compute analytically in this elective, you'll test against a central difference. In ML engineering this is called a gradient check, and it's the first test to write for any hand-written backward pass.
</Listen>

```text
one-sided:  (f(x+h) - f(x)) / h          = f'(x) + (h/2) f''(x) + O(h^2)
central:    (f(x+h) - f(x-h)) / (2h)     = f'(x) + (h^2/6) f'''(x) + O(h^4)
```

## Expressions as graphs, and local derivatives

Write a computation as a directed acyclic graph: leaves are inputs and parameters, interior nodes are elementary operations, and one node is the output, usually called L for loss. The video's neuron is a good running example: n = x1 w1 + x2 w2 + b, and o = tanh(n).

Each operation knows its **local derivatives**, the partial derivatives of its output with respect to its own inputs, and nothing else:

- Addition c = a + b: the partial of c with respect to a is 1, and with respect to b is 1. Addition routes gradient unchanged to both inputs.
- Multiplication c = a times b: the partial with respect to a is b, and with respect to b is a. Multiplication swaps.
- tanh: if t = tanh(n), then dt/dn = 1 minus t squared. Conveniently, this uses the output t, which the forward pass already computed.

The **chain rule** composes them. If L depends on c and c depends on a, then dL/da = (dL/dc)(dc/da). Backpropagation is that rule applied node by node from the output back to the leaves: each node receives dL/d(itself) from downstream, multiplies by its local derivative, and passes the result to its inputs.
</Listen>

## The chain rule is a sum over paths

The single most important detail in this lecture is what happens when a value is used more than once. Suppose L depends on a through two intermediate nodes, c and d. The multivariable chain rule says the partial of L with respect to a is the sum: (partial L over partial c)(partial c over partial a) plus (partial L over partial d)(partial d over partial a). In general, the derivative of the output with respect to any node is the sum, over every path from that node to the output, of the product of local derivatives along the path.

In code, that sum becomes accumulation. Each node's gradient starts at zero, and every consumer adds its contribution: `self.grad += ...`, never `self.grad = ...`. The video discovers the overwrite version at 01:22:28 with b = a + a, whose gradient should be 2 and comes out as 1.

Two consequences follow. First, a node can only pass gradient on once every consumer has added its share. That's why the backward pass visits nodes in **reverse topological order** (every node after all nodes that depend on it). Second, gradients must be reset to zero before each new backward pass, or the next pass adds on top of the old one. You'll meet that second bug in the training loop next lesson.
</Listen>

```text
L = f(c, d),  c = g(a),  d = h(a)

dL/da = (dL/dc)(dc/da) + (dL/dd)(dd/da)          <- one term per path from a to L

example: b = a*a + a
db/da  = a + a + 1 = 2a + 1     (the product contributes a twice, the sum contributes 1)
```

## Why reverse mode, and what it costs

There are two ways to apply the chain rule mechanically. **Forward mode** picks one input and pushes "derivative with respect to this input" forward through the graph alongside the values. **Reverse mode** picks one output and pulls "derivative of this output" backward to all inputs. Baydin and colleagues' survey of automatic differentiation lays out the trade-off: for a function from R^n to R^m, forward mode needs about n passes to get the full Jacobian and reverse mode needs about m.

Training a network means differentiating a single scalar loss with respect to every parameter, so m = 1 and n can be billions. One reverse pass gives the whole gradient for a small constant multiple of the cost of the forward pass. That asymmetry is the entire reason backpropagation, popularized for neural networks by Rumelhart, Hinton, and Williams in 1986, is the workhorse of deep learning.

The price is memory. Reverse mode needs the forward pass's intermediate values (here, `t` inside tanh's backward, and both operands inside multiply's), so it keeps them until the backward pass consumes them. Baydin and colleagues name this storage requirement as the main drawback of reverse mode. Scaled up to large networks, it is why training needs far more memory than running the same model, a point you'll hear again whenever people discuss fine-tuning budgets.
</Listen>

<Callout type="pitfall" title="Three bugs that pass a casual test">
**Overwriting instead of accumulating** gives correct gradients on every expression where each value is used once, then silently wrong ones as soon as a weight is shared. **Visiting nodes in the wrong order** has the same property: trees work, DAGs don't. **Forgetting to wrap constants** (`c * 4`) crashes rather than misleads, which is the friendly kind of bug. The defense for the first two is the same: always include a reused node in your tests, and always compare against a numerical gradient rather than against what you expect.
</Callout>

## Checks and balances, from the first lesson

You just wrote a test that compares an analytic gradient against a finite-difference estimate. Hold onto that habit; it is the most transferable thing in this lesson. When you later write a custom loss, a custom layer, or a fine-tuning script that does anything nonstandard, a gradient check on a tiny input is the fastest way to know whether the math in your code is the math in your head.

Two practical notes on doing it well. Use the central difference with h around 1e-5 to 1e-6 in double precision, and compare with a **relative** error (the absolute difference divided by the sum of magnitudes), because gradients span many orders of magnitude. And check on small, random, non-symmetric inputs. Symmetric inputs such as all-ones can hide a swapped index, because the wrong entry happens to have the right value.

The same idea, testing a component against an independent method rather than against your expectations, is what Studio 3 calls evaluation. Here the independent method is calculus; there it is labeled data or a second grader.
</Listen>

<GoDeeper title="Jacobians, and what PyTorch calls a vector-Jacobian product">
In vector form, a node computes y = f(x) with x in R^n and y in R^m, and its local derivative is the m-by-n Jacobian J. Reverse mode never forms J. It receives the row vector g = dL/dy and computes g J, a **vector-Jacobian product**, which is all the inputs need. For elementwise operations like tanh, J is diagonal, so g J is just g times the local derivative elementwise; for a matrix multiply it becomes another matrix multiply. That's exactly what micrograd's per-operation `_backward` closures do at the scalar level, and what frameworks do at the tensor level. Baydin and colleagues' survey covers forward mode (Jacobian-vector products, computed with dual numbers) and reverse mode in detail, and chapter 6.5 of Goodfellow, Bengio, and Courville's *Deep Learning* gives the textbook treatment of back-propagation as dynamic programming over the graph. In lesson 6 you'll derive the tensor-level versions by hand.
</GoDeeper>

## Review sheet

A derivative can be estimated by nudging; the central difference is accurate to order h squared and is your independent check. Reverse mode gets the gradient of one output with respect to all inputs in one pass, at the cost of storing the forward pass.
