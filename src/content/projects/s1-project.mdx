## The brief

Every team loses action items in meetings. Someone says "I'll get that to you by Friday," and it lives only in a transcript nobody rereads. You will build a tool that reads a transcript and returns the commitments people made, in a form a project tracker can use.

The trap in this problem is that a model will happily produce a plausible list. Some items will be real, some will be paraphrased discussion, some will have the wrong owner, and a few dates will be confidently miscalculated. The job is not to get a list. The job is to get a list **you can trust**, and to prove how trustworthy it is. That's why this project is graded on verification and measurement as much as on extraction.

## What you get

Sample data, all fictional:

- [meeting-01-sprint-planning.txt](../../project-data/s1/meeting-01-sprint-planning.txt), [meeting-02-customer-escalation.txt](../../project-data/s1/meeting-02-customer-escalation.txt), [meeting-03-retro.txt](../../project-data/s1/meeting-03-retro.txt): three short transcripts with a meeting date in the header.
- [team.json](../../project-data/s1/team.json): a team directory with names and aliases.
- [gold.json](../../project-data/s1/gold.json): hand-labeled action items for each transcript, with the labeling rules at the top. Read the rules: deciding what counts as an action item is half the problem.

The samples contain deliberate traps: an alias that collides with a common abbreviation, a task that gets reassigned mid-conversation, ideas that are explicitly declined, and a commitment whose owner is the speaker but whose evidence is someone else's line. Your evaluation should catch them.

<Callout type="tip" title="Start with the eval, not the prompt">
Write the scoring script first. Decide how you will match a predicted item to a gold item (same owner and an evidence quote that overlaps?), compute precision and recall, and run it on an empty prediction file. Then every prompt change you make has a number attached. This habit is the whole of Studio 3 in miniature.
</Callout>

<Callout type="pitfall" title="Letting the model do arithmetic on dates">
"End of next week" from a Monday meeting is a calendar calculation, and models get these wrong often enough to matter. Have the model extract the phrase as said, and resolve it in code against the meeting date. Same idea for owners: extract the name as said, then look it up.
</Callout>

## Constraints

- Use the official Anthropic SDK (or another provider's official SDK if you prefer, but justify it). Keep keys in environment variables.
- A full run over the gold set should cost under 25 cents. Log it and prove it.
- The offline test suite must run without an API key, using a fake client.
